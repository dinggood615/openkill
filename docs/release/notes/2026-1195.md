# OpenKill 2026-1195

## NaiveProxy 独立组件

- 修复 LuCI 控制请求在当前 ucode/LuCI 运行时因文件权限参数类型不兼容而被提前拒绝的问题；控制请求改为独立的受保护请求文件和 fork/exec 子进程，返回逐请求结果和失败阶段。
- 修复请求管道被 NaiveProxy 进程继承、启动时加载器环境污染和重复注册实例的问题；启动、停止、编辑应用均采用有界等待并验证真实实例。
- 监听健康状态必须通过 PID、配置代数和 `/proc` socket inode 关联确认；外部占用、未知归属和远端 HTTPS 探测失败分别报告。
- 健康检测不再生成或覆盖运行配置；停止、编辑和删除会使旧检测结果失效。

## LuCI 与隐私

- 导入表单不再对新节点错误显示“保留当前密码”；编辑时密码保持受保护且可单独应用。
- 保存、保存并启动、单节点启停和重试保留清晰阶段；状态仅展示已取得的证据，Mihomo 手动 YAML 接入无法可靠读取时仍显示“未验证”。
- 节点和端口数据继续由设备独立目录保存，项目源码、安装包和默认配置不携带个人节点或凭据。

## 安全与升级

节点目录保持 700，节点与运行配置保持 600；凭据不进入命令行、日志、Mihomo YAML 或普通状态响应。升级前保留 `/etc/config/openkill`、`/etc/openkill` 和 `/etc/naiveproxy`，失败可恢复上一正式版及备份。下载保持 TLS 证书校验，不修改 DNS、防火墙、路由或 TUN。

## 验证范围

在授权 OpenWrt x86_64 测试机上通过真实 LuCI 完成导入、保存、保存并启动、停止、再启动、保留密码编辑应用和节点测试；经独立 SOCKS5 对两个 HTTPS 目标连续三轮成功。当前运行 Mihomo 的专用代理组经该回环节点完成两个 HTTPS 请求并恢复原选择。正式候选包和正式包安装后的结果记录在执行计划中。
