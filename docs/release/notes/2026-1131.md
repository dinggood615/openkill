# OpenKill 2026-1131

## Changes

- Align the runtime dashboard into equal-width, content-sized cards and keep
  the configuration, compatibility and resource areas aligned at responsive
  breakpoints.
- Keep DNS privacy, ad blocking, OpenVPN compatibility and RustDesk state
  independent in the UI; distinguish requested, generated, applied and
  verified states.
- Use the maintained anti-AD source as a bounded fallback when the configured
  source is unavailable, preserving the last valid list and DNS privacy.
- Correct the OpenVPN disabled-transport state so `applied=0` is reported when
  no bypass rules were generated.

## Migration and compatibility

- Existing UCI configuration, PassWall configuration and legacy service-port
  objects are preserved. OpenVPN transport bypass remains opt-in and scoped
  to configured endpoints, protocols, ports and clients.
- A failed adblock download keeps the last valid cache; if none exists the
  UI reports that filtering is unavailable without disabling DNS privacy.
- No CENTRAL_ACTIVE state, central nft apply, full-LAN bypass, IPv6 disable or
  broad RustDesk/OpenVPN port exemption is introduced.

## Validation scope and limitations

- Local OpenVPN, optimization, UI contract/preview/interaction, shell and
  local-gate checks passed. Exact master Development CI passed for the source
  commits used for this release.
- The authorized Kwrt device installed and restarted the candidate, preserved
  the user configuration, loaded the maintained adblock fallback and reported
  the corrected OpenVPN disabled state. Strict DNS egress, public IPv6,
  RustDesk client connectivity, OpenVPN handshake/tunnel business traffic and
  packet-path performance remain unverified because the required external
  clients/services were not available.
- Keep the previous release and the protected device backup for rollback.
