# OpenKill 2026-1128

Local delivery and release-workflow follow-up to 2026-1127.

## Changes

- Development pushes validate source, semantic contracts, runtime integration
  and official Mihomo compatibility without publishing a package.
- RC builds remain manual and artifact-only. Formal publication requires the
  explicit release gate and reviewed notes for the source version.
- Publishing preserves existing releases and tags. Missing notes fail before
  publication. Downloaded package bytes are verified against the built asset
  before the package channel is updated.
- Developer entry points, fixture isolation, architecture and execution-state
  documentation are recorded in the repository. No new DNS, firewall, parser,
  routing or core behavior is introduced by this release.

## Validation scope and remaining gaps

Post-D2C DNS CURRENT intent reconciliation is locally tested: mode-1 firewall
interception targets dnsmasq :53, with upstream and Mihomo listener modeled
independently at 127.0.0.1:7874. This is not a claim of current device parity.

- Post-D2C real-device semantic revalidation: PENDING / NOT_TESTED in this release.
- Real packet path, throughput and device IPv4/IPv6 acceptance: NOT_TESTED.
- Access overlap and TPROXY device coverage: NOT_OBSERVED.
- TUN BC-04 remains the documented CURRENT gap.
- Legacy writers remain authoritative. Shadow remains disabled by default.
- CENTRAL_ACTIVE and CENTRAL_NFT_APPLY are NOT APPROVED; Phase 4 is deferred.

This release is supported by local fixtures, development CI and package build
checks. It does not certify router readiness from those checks. Existing
releases are retained; users requiring post-D2C device evidence should wait
for separately authorized device validation.
