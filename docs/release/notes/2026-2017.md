# OpenKill 2026-2017

## DNS forwarding mode separation

- Dnsmasq forwarding keeps the existing client → dnsmasq → Mihomo path.
- Firewall forwarding now targets the Mihomo DNS listener directly and does not
  add an OpenKill dnsmasq upstream include.
- Direct mode promotes loopback DNS configuration to a dual-stack listener,
  validates the Mihomo owner and both UDP/TCP transports, and reports an
  incomplete firewall path instead of claiming readiness.
- Recovery checkpoints now record the DNS frontend mode and listener so a
  snapshot from the other forwarding mode cannot be reused.
- Ruby/YAML generation stderr is retained in the protected OpenKill log to make
  validation failures actionable while preserving the active configuration.
