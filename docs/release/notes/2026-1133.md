# OpenKill 2026-1133

## Changes

- Add the optional NaiveProxy helper integration. OpenKill keeps Mihomo as
  the transparent core and exposes each configured NaiveProxy endpoint as a
  loopback SOCKS5 bridge, so existing proxy groups can use it without
  claiming native Mihomo Naive support.
- Add guarded component installation, stable per-node loopback ports,
  readiness-aware startup, credential-safe JSON configuration and explicit
  local/remote verification states.
- Document the helper's anti-loop ownership contract and retain conservative
  failure behavior: a missing or unhealthy helper never silently becomes
  DIRECT.

## Migration and compatibility

- NaiveProxy is optional and remains disabled until a user enables it and
  configures a node. Existing nodes, subscriptions, transparent modes, DNS,
  adblock, IPv4/IPv6 bypass, RustDesk and OpenVPN settings keep their prior
  behavior.
- The helper requires a compatible OpenWrt architecture/libc and an official
  HTTPS artifact with a user-supplied SHA256. Unsupported architectures and
  invalid artifacts are rejected without replacing the last working binary.
- The bridge currently advertises TCP SOCKS5 only (`udp: false`) until a
  separately verified UDP path exists.

## Validation scope and limitations

- Local integration, shell syntax, UI contract/preview and local-gate checks
  passed on the release source commit. Formal CI also runs the runtime and
  package checks.
- No real NaiveProxy server or device packet-path test is bundled with this
  release; remote authentication, UDP behavior, live DNS egress and client
  connectivity remain unverified without those external conditions.
- Keep the previous `2026-1132` release and device backups available for
  rollback.
