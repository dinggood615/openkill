# OpenKill 2026-2020

## Telegram UDP transport compatibility

- Keep the user's existing Telegram selector and TCP rules unchanged.
- Add a managed, protocol-scoped UDP path when the generated configuration has
  concrete UDP-capable proxies or an explicitly named UDP proxy group.
- Generate IPv4 and IPv6 Telegram UDP rules with Mihomo's `AND` matcher; do not
  add `DIRECT`, disable TLS, or change the default business proxy group.
- If no usable UDP path is available, preserve the original configuration and
  expose a diagnostic reason instead of claiming that Telegram is supported.
- The runtime status page reports the generated UDP path as diagnostic data;
  it does not turn Telegram connectivity into a generic feature toggle.

The fix is intentionally narrower than a blanket UDP/443 allow rule.  A real
Telegram client session is still required to validate login, media and calls;
the release gate does not treat YouTube/TikTok HTTPS success or a controller
delay probe as proof of those application paths.
