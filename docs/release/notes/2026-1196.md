# OpenKill 2026-1196

## NaiveProxy 独立组件

- 修复分享链接首尾空白在前端预览成功、提交时却被控制器判为
  `request-validation` 的问题；前后端统一裁剪链接边界空白，内部控制字符仍拒绝。
- 健康检测改为纯观测：缺少已应用运行配置时报告未应用，不生成配置、不分配端口、不覆盖节点数据。
- 端口分配增加受保护锁、原子映射更新，并检查所有本机监听地址，避免并发竞争和通配/IPv6 冲突误判。
- 重启后的只读组件状态刷新仅更新组件证据，不重建节点配置或端口映射。

## Mihomo 接入与隐私

- 独立 Naive SOCKS5 仍通过用户 YAML 手动接入；测试可使用仅回环、无凭据的专用 Mihomo 监听，默认策略和用户 YAML 不被自动改写。
- 节点、凭据、端口映射和运行配置继续保存在设备受保护目录，源码、默认配置、构建缓存和发布包不携带个人节点数据。

## 升级与验证

升级前保留 `/etc/config/openkill`、`/etc/openkill` 和 `/etc/naiveproxy`；失败时恢复上一正式包及受保护备份。下载保持 TLS 证书校验，不修改 WAN、DNS、防火墙、路由或 TUN。

本版本在授权 OpenWrt x86_64 测试机完成独立 SOCKS5、双目标 HTTPS、多实例隔离及当前 Mihomo 专用回环入口验证。Chrome 浏览器自动化会话若不可见，则仅记录设备侧 LuCI HTTP 结果，不将其表述为浏览器视觉验收。
