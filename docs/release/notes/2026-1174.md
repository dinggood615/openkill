# OpenKill 2026-1174

## 变更

- 修复独立 NaiveProxy 控制结果的原子写入：可选结果字段为空时，先前的
  shell 分支会遗漏控制结果文件，导致页面无法可靠地获取导入或保存阶段。
- 组件区域现在显示实际路径、版本、资产、机器架构及失败阶段，并提供重新
  检测、安装组件、检查更新、更新稳定版与诊断操作。安装沿用一键安装的
  官方制品校验和原子替换路径；并发安装会被独立锁拒绝。
- 分享链接导入支持经过验证的 HTTPS 与 QUIC 方案；节点可受保护地重读和
  编辑，支持保留原密码、配置代次冲突提示和稳定本地端口。OpenKill 继续不
  写入 Naive 凭据、用户 YAML 或策略组。

## 验证边界与回滚

- 本地独立服务夹具覆盖导入、持久化、重复拒绝、编辑、密码保留、代次冲突、
  组件替换失败保留旧版本和健康状态；生产模板的 Playwright 测试覆盖导入、
  保存、编辑与窄屏布局。
- 未执行设备写入、组件安装、真实 NaiveProxy 二进制探测、进程/PID/监听或
  VPS 探测。它们仍为设备待验证／远端待验证；本版本不改变 WAN、DNS、路由、
  nft、用户 YAML 或分流策略。
- 回滚可安装 `v2026-1173-ipk`；独立节点数据位于 `/etc/naiveproxy/`，用户
  YAML 不由 OpenKill 修改。

## 发布证据

本文件的精确 Development CI、RC 审计、Formal Release 和正式包 SHA256 将在
相应门禁成功后记录于执行计划；发布前不得把本地夹具结果描述为设备或 VPS
连通。
