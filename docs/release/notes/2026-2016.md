# OpenKill 2026-2016

## 分离本地 DNS 转发路径

- `Dnsmasq 转发` 保持原有链路：授权客户端 DNS → dnsmasq → Mihomo DNS；dnsmasq 继续承载局域网名称、条件转发和 dnsmasq 侧广告视图。
- `防火墙转发` 改为直接链路：授权客户端的 IPv4/IPv6 UDP/TCP 53 → OpenKill 自有防火墙接管链 → Mihomo DNS 监听。该模式不再把 dnsmasq 作为中间 DNS 转发器。
- 直接模式在默认回环监听不适合 REDIRECT 时使用双栈 Mihomo 监听；启动就绪同时核对入口跳转、受管子链、目标端口、UDP/TCP 监听、地址族和 Mihomo 进程归属。
- 自定义域名 DNS 在直接模式生成为 Mihomo `nameserver-policy`；dnsmasq include、dnsmasq 上游改写和 dnsmasq 广告 include 仅用于模式 1。配置生成失败保持原配置，不静默切回明文或 DIRECT。

## 兼容与升级

- 保留现有 UCI 键、节点、订阅、源/生成 YAML、代理组选择及独立组件数据。升级和同版本重装不重置用户选择；缺失字段仍由幂等归一化补齐。
- `dns_port` 继续表示 Mihomo DNS 监听端口；模式 1的防火墙目标使用实际 dnsmasq 端口，模式 2使用 Mihomo DNS 端口。切换模式会清理仅由 OpenKill 管理的旧 dnsmasq include/规则。
- 旧版本已有的用户 dnsmasq 状态在模式切回或服务停止时按备份恢复。模式 2不删除用户自有 dnsmasq 配置。

## 验证边界

- 本地 DNS 意图、运行时、nft IR、LuCI 合同和安装门禁覆盖两种路径及双栈规则模型；真实设备与候选/正式包结果记录在 `docs/exec-plans/CURRENT.md`。
- DNS 防泄漏结论只覆盖实际经过授权设备的客户端路径；浏览器自建 DoH、没有活动 OpenVPN 客户端的隧道业务以及服务停止后的系统解析不被本版本宣称覆盖。
