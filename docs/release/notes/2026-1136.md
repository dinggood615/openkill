# OpenKill 2026-1136

## Changes

- Hide the legacy top-level NaiveProxy menu while preserving its bookmark
  redirect into Plugin Settings → Compatibility.
- Place OpenVPN exact compatibility and the NaiveProxy helper in the shared
  responsive two-column settings grid.
- Add an explicit “automatic match and install” action for the official
  NaiveProxy component. Metadata discovery now fills only an empty, matching
  URL/SHA256 pair as a form draft and never commits UCI by itself.
- Add links from Compatibility to the existing NaiveProxy node editor and
  strategy-group manager. Existing stable node identities and loopback SOCKS5
  generation remain unchanged.
- Harden release-tag and digest validation in the offline-safe metadata parser.

## Migration and compatibility

- Existing NaiveProxy fields, nodes, subscriptions, routing, DNS and unrelated
  compatibility settings are preserved. NaiveProxy remains opt-in and is not
  installed or enabled merely by opening the settings page.
- A partially filled manual URL/SHA256 pair is preserved and is never mixed
  with metadata from another release. Save and Apply remains the persistence
  boundary for settings.
- The legacy `/naive` URL continues to redirect to the Compatibility tab.

## Validation scope and limitations

- Local NaiveProxy integration, UI contract/preview, JavaScript syntax,
  POSIX syntax, local-gate, exact-commit Development CI and package audits are
  required for this release.
- No device installation, remote NaiveProxy authentication or live packet-path
  test is included; local bridge generation and remote endpoint behavior remain
  device-dependent.
- UDP forwarding remains disabled until separately verified.
