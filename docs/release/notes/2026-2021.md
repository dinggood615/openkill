# OpenKill 2026-2021

## Telegram routing regression rollback

- Removed the 2026-2020 automatic Telegram UDP group and protocol-specific rule injection.
- Telegram traffic again uses the user's existing rules and proxy-group selection; no new application-specific group, DIRECT fallback, or hidden switch is added.
- The status page no longer reports generated Telegram transport readiness, avoiding a configuration-only success signal that was not backed by a real Telegram client session.
- This is a deliberately minimal rollback while the remaining Telegram login path is verified with a real client. The release does not claim Telegram login, media, or calls are validated unless those client-level tests are recorded separately.

## Verification boundary

- Existing DNS, TUN, firewall, IPv4/IPv6, domestic direct-routing, NaiveProxy, and user proxy-group semantics are unchanged by this release.
- Development, RC, and formal package gates must pass. A real Telegram client login remains a hard device acceptance gate; if the client is unavailable, retain the candidate and record the blocker instead of claiming application-level success.
