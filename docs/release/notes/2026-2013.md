# OpenKill 2026-2013

## DNS, dual-stack and routing performance

- Strict DNS now supports an explicit, managed `url-test` or ordered
  `fallback` DNS egress strategy. The strategy affects DNS transport only;
  domestic business rules remain in the user's existing direct/proxy policy.
- Custom health-check URLs keep their configured expected status. The built-in
  `generate_204` default is the only endpoint that receives the 204 default.
- DNS generation and validation use the same strategy and preserve a bounded
  `fallback-lazy-query` setting, avoiding duplicate selector interpretation.
- IPv4/IPv6 OpenVPN endpoint discovery collects both address families and the
  legacy ipset path promotes complete sets transactionally, restoring the
  previous generation if a swap fails.

## Ad blocking

- Standard mode is considered enabled when its DNS list is loaded; enhanced
  mode additionally requires the generated core provider to be loaded.
- Maintained anti-AD and HaGeZi supplements can be selected for enhanced mode.
  Downloads are HTTPS-only, size/content checked, cached per source, merged
  with deduplication and replaced atomically; a failed update keeps the last
  valid list. The checked-in source choices are the upstream anti-AD list and
  HaGeZi DNS blocklists; their upstream licenses and maintenance status remain
  the source of truth, and no list content is bundled in the package.

## NaiveProxy component updates

- Updates are serialized, space-checked and staged in a protected temporary
  directory. The executable, matching metadata and active instances are
  updated as one transaction.
- A mode/architecture/version probe runs before activation. The previous
  executable and metadata remain in a 0700/0600 rollback generation, and an
  activation or rollback-record failure restores the prior instance state.

## Defaults and validation boundary

- Fresh installs use the reviewed `performance-dual-stack` profile, strict
  DNS with the low-delay `url-test` strategy, enhanced ad blocking defaults,
  and firewall DNS forwarding. Upgrades and same-version reinstalls preserve
  existing user values; no node, subscription, credential, device or YAML
  data is packaged as a default.
- This release was validated with local and isolated fixtures only. No router,
  test platform, iPhone, live packet capture or real-device installation was
  performed, so device-specific DNS leakage and cellular behaviour remain
  outside the release evidence.
