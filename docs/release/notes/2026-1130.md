# OpenKill 2026-1130

## Changes

- Add opt-in OpenVPN transport compatibility with separate IPv4/IPv6 endpoint
  and client scopes, explicit TCP/UDP family selection, staged updates and
  last-valid retention. Tunnel traffic and DNS policy remain independent.
- Show DNS privacy, ad blocking and OpenVPN requested/generated/applied state
  in separate dashboard cards, including unverified tunnel and business state.
- Keep the responsive dark status layout content-sized and make stopped,
  failed and unavailable runtime states recoverable in the UI.
- Preserve the existing DNS listener split, adblock generation contract,
  RustDesk scoped rules, IPv4/IPv6 region-set safety and legacy service-port
  ABI.

## Migration and compatibility

- OpenVPN compatibility and transport bypass remain disabled by default. No
  broad VPN subnet, LAN range, all-443/all-1194 rule or automatic DIRECT rule
  is added during upgrade.
- Existing OpenKill, PassWall, DNS and firewall configuration is preserved.
  OpenVPN settings are normalized to safe disabled defaults when absent.
- Legacy `remote_service_bypass` and `openkill_service_ports` remain separate
  from the new OpenVPN-owned sets. Unsupported native-owner combinations are
  reported as unsupported instead of silently applied.

## Validation scope and limitations

- Local OpenVPN contract, UI, DNS intent, optimization, POSIX/BusyBox shell,
  runtime and installer fixtures pass; exact master Development CI and the
  OpenWrt SDK RC audit pass for the source used here.
- The authorized Kwrt device installed the RC candidate and passed package
  hash, configuration-preservation, fail-closed startup/stop and nft residue
  checks. It has no Mihomo core/profile, usable proxy, running OpenVPN tunnel
  or RustDesk test client, so strict DNS egress, adblock traffic coverage,
  region packet paths, RustDesk recovery and OpenVPN handshake/tunnel business
  remain unverified.
- No CENTRAL_ACTIVE state, central nft apply, WAN/VMware change, IPv6 disable,
  full-LAN bypass or packet-path benchmark was used. Keep the previous release
  and the protected device backup for rollback.
