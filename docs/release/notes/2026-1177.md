# OpenKill 2026-1177

## NaiveProxy independent service

- fix the OpenWrt procd lifecycle so instances are committed before bounded
  readiness verification and per-instance state is recorded only after the
  matching process and listener are visible;
- register the explicit `start_node`, `stop_node` and `health` init commands,
  use the real bridge service/instance names for targeted control, and keep
  disabled nodes out of the start result;
- run the official NaiveProxy process with its required root group so a local
  SOCKS5 listener can establish the upstream TLS tunnel;
- preserve active runtime configuration during health probes and expose the
  component-to-Mihomo evidence flow in LuCI.

## Upgrade and rollback

Install the package through the OpenKill updater or LuCI. Existing node files,
stable port mappings and user Mihomo YAML are retained. Apply edited nodes
again after upgrading if the UI reports a pending apply. Stop the independent
bridge before restoring the protected backup, then reinstall the previous
package to roll back.

## Verification

Local behavior and POSIX gates pass. On the authorized OpenWrt x86_64 test
machine, the real saved Naive node starts under procd, passes two HTTPS targets
through SOCKS5 before and after a stop/start cycle, and a temporary Mihomo
configuration routes the same targets through the loopback SOCKS5. LuCI visual
browser automation was not completed because the browser bridge timed out;
the production-template UI tests remain passing. Full formal-release and
device package-install evidence is recorded in the execution plan.
