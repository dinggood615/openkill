# OpenKill 2026-1209

## 修复

- “防火墙转发”不再因 TUN、IPv6 或回环监听被前端校验拒绝，也不会在配置归一化时被静默改回 dnsmasq。
- fw4 防火墙转发补齐 IPv4/IPv6 的 UDP/TCP 53 重定向，并在就绪检查中核对真实重定向规则；fw3/iptables 路径补齐 IPv6 DNS 转发及幂等跳转。
- LAN 访问控制只有 IP 或只有 MAC 白名单时不再引用不存在的防火墙集合；无有效白名单时应用失败并保留原配置。
- 节点域名解析在显式原生 DNS 返回 Fake-IP 后不会再通过 getent/系统 resolv.conf 绕过该解析链路，避免把合成地址错误写入节点 underlay。

## UI

- “网络与分流”页将局域网设备访问控制、WAN 访问控制和来源流量规则分为独立卡片；来源规则保持全宽、窄屏可滚动。
- “本地 DNS 劫持”选项名称统一为“防火墙转发”，帮助说明改为描述实际 UDP/TCP 53 重定向语义。

## 兼容性与限制

- 保持 dnsmasq 转发为默认模式；防火墙转发仍需本机 Mihomo DNS 监听和可用的防火墙能力，应用前会执行有界就绪检查。
- fw4 设备会安装 IPv4/IPv6 规则；没有可用 ip6tables 表的 fw3 设备仅能验证其 IPv4 路径，诊断中保留该限制。
- 不修改用户节点、订阅、YAML、WAN、TUN 接管策略或默认代理组。

## 升级与回滚

升级后在“网络与分流”页选择“防火墙转发”，保存并应用配置，再验证本机 DNS 监听及客户端 UDP/TCP 53 查询。若应用失败，OpenKill 保留原可用配置；可安装上一正式版 IPK 并恢复受保护备份回滚。
