# OpenKill 2026-2015

## OpenVPN 与防火墙 DNS 转发

- 修复“本地 DNS 劫持 → 防火墙转发”在 OpenVPN 隧道客户端上的双栈入口不一致：IPv4/IPv6 的 UDP/TCP 53 现在统一重定向到受控 dnsmasq 前端，再由 dnsmasq 转发到 Mihomo 的回环 DNS 监听。
- 保留防火墙模式独立的访问控制链、路由策略和用户 DNS 隐私设置；不把 Mihomo 的回环端口直接作为入站 REDIRECT 目标，避免隧道地址无法到达核心。
- 就绪检查现在按入口跳转、地址族规则、目标端口、对应 UDP/TCP 监听及 dnsmasq 进程归属共同判断；旧的 IPv4 直达 Mihomo 规则会被重建，IPv6/legacy 能力缺失时明确失败。
- OpenVPN `inherit` DNS 模式沿用现有隐私策略，并通过双栈 dnsmasq 入口承接授权隧道内 DNS；不自动接受全局推送 DNS，不改变用户节点、代理组、WAN 或全网路由。

## 兼容与升级

- 保留 `dns_port` 作为 Mihomo 监听和 dnsmasq 上游端口；防火墙入口端口单独取 dnsmasq 实例的实际监听端口（默认 53）。
- 升级和同版本重装保留现有 UCI、源/生成 YAML、节点、订阅及独立组件；配置缺失字段通过幂等归一化补齐。
- 仅 OpenKill 自有 DNS 接管规则会被重建；停止、模式切换及失败恢复只清理本组件规则。

## 验证边界

本版本包含本地 shell/语义回归、fw4/legacy 规则模型及已授权设备上的候选/正式安装验证。实际设备验收记录会在 `docs/exec-plans/CURRENT.md` 中补充，DNS 防泄漏结论仅覆盖经过测试机的客户端路径，不包含浏览器自建 DoH 或服务停止后的系统解析。
