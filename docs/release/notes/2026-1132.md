# OpenKill 2026-1132

## Changes

- Share one lower dashboard grid between the configuration column and the
  resource column. The eight existing resource metrics now render as two
  columns by four rows on desktop, so the right edge ends with the real
  metrics instead of an unowned blank area.
- Expose separate adblock generation, DNS backend, core provider and verified
  evidence to the status endpoint. The runtime page now reports generated,
  loaded, failed and verified states conservatively instead of calling a
  generated rule set "effective" when loading is unknown.
- Report OpenVPN transport bypass independently from compatibility configuration
  so a configured feature with bypass disabled is shown as disabled rather than
  applied.

## Migration and compatibility

- Existing DOM IDs, controls, UCI configuration and service contracts remain
  unchanged. The dashboard layout is responsive and uses no placeholder card,
  fixed-height spacer or broad network exemption.
- Existing adblock state files remain readable; older files without the new
  evidence fields are displayed as generated or unknown until a new generation
  writes the explicit state fields.

## Validation scope and limitations

- UI contract, local preview, OpenVPN compatibility, optimization and local
  gate checks passed. The preview was rendered from the production template and
  final CSS at a 1920px desktop viewport; narrow viewport rendering remains a
  separate responsive check.
- Device verification covers package/resource hashes, service readiness and
  status state generation. Live browser login rendering, strict DNS egress,
  public IPv6, RustDesk client connectivity and OpenVPN tunnel business traffic
  remain unverified without the required external clients and services.
- Keep the previous 2026-1131 release and the protected device backup for
  rollback.
